# Monid Example Skills

A catalog of [Monid CLI](https://github.com/monid-ai/cli) examples packaged as
**installable agent skills**. Each skill is a self-contained recipe that teaches
a coding agent (or a human) how to solve one real task using
`monid discover → inspect → run`.

Built on the open [agent-skills spec](https://agentskills.io). Works with Claude Code,
Codex, Cursor, OpenCode, Gemini CLI, and [50+ other agents](https://github.com/vercel-labs/skills#supported-agents).

## Install

```bash
# Browse what's in the catalog (same list as the index above)
npx skills add monid-ai/skills --list

# Install a single skill — swap <skill> for any name from the index
npx skills add monid-ai/skills -s <skill>

# Install to a specific agent
npx skills add monid-ai/skills -s <skill> -a claude-code
```

For example, to install the `investor-sourcing` skill from the index above:

```bash
npx skills add monid-ai/skills -s investor-sourcing
```

After install, your agent will pick up the skill automatically next session.

Each skill is **self-contained** — its `SKILL.md` walks the agent through
installing the [Monid CLI](https://github.com/monid-ai/cli), funding a key, and
any other one-time setup. You don't need to read anything else first.

## Use without the skills CLI

Every skill ships standalone. Clone the repo and read its `SKILL.md`, or run
its bundled script directly if it has one (swap in any skill from the index):

```bash
git clone https://github.com/monid-ai/skills
cd skills/skills/investor-sourcing
cat SKILL.md
```

## Contributing a new skill

See [AGENTS.md](AGENTS.md). The short version:

```bash
mkdir skills/my-new-skill
$EDITOR skills/my-new-skill/SKILL.md          # required: YAML frontmatter (name, description, version)
cd scripts && deno task validate              # regenerates the skill index in this README
git add skills/my-new-skill && git commit -m "Add my-new-skill"
```

Use [`skills/investor-sourcing/SKILL.md`](skills/investor-sourcing/SKILL.md) as
a reference for the conventions (frontmatter shape, preflight checks,
explaining cost to the user, etc.).

Rules of thumb:

- Folder name = `SKILL.md` frontmatter `name` (lowercase, hyphens).
- Bump `version:` whenever you change the instructions.
- Per-user state goes under `${XDG_DATA_HOME:-$HOME/.local/share}/monid/<skill-name>/`
  — never `~/.<skill-name>/`. See `investor-sourcing` for the reference shape.
- Each `SKILL.md` is standalone — it must explain Monid setup itself so users
  don't need to read this README first.
- If you ship a `run.sh`, keep `inputs.example.json` minimal (`maxItems: 5` etc.)
  so the example is cheap to try.
- Include a `sample-output.json` (redacted) so users see the result shape before
  paying.
